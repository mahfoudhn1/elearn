# Phase A4 — Flashcards (Leitner spaced repetition)

Status: **implemented.** Adds flashcards, per-student Leitner state, idempotent
reviews and a pure spaced-repetition engine to the `assessment` app. Mounted at
`/api/assessment/`.

Out of scope (delivered later): UI, planner integration.

Companion docs: `docs/assessment/A1.md` (content), `A2.md` (quizzes + evidence),
`A3.md` (mastery + readiness), `docs/TO_VERIFY.md`.

---

## 1. Rule set (JSON, schema-validated)

File: `backend/assessment/rules/leitner_default_v1.json`
Schema: `backend/assessment/leitner_schema.py` (`validate_leitner_rules`)
Loader/DTO: `backend/assessment/engine/leitner_rules.py` (`load_leitner_rules`)

Every number carries a sibling `why`; the schema rejects a missing `why`. All
values are **placeholders** (`verified: false`) tracked in `docs/TO_VERIFY.md`.

| Key | Meaning |
|---|---|
| `max_box` | highest Leitner box (a card graduates here) |
| `box_intervals_days.{1..5}` | days until due for each box |
| `rating_box_delta.{AGAIN,HARD,GOOD,EASY}` | box move per rating (AGAIN is a reset sentinel) |
| `rating_score.{AGAIN,HARD,GOOD,EASY}` | evidence score (0..1) mapped from the rating |
| `overdue_interval_days` | (reserved) schedule from now, never from the old due date |
| `new_cards_per_day` | cap on brand-new cards surfaced per day |
| `lapse_score_penalty` | extra multiplier on the score when a card lapses |

## 2. Pure engine (`assessment/engine/leitner.py`)

No Django, no DB, no clock: callers pass `now` in.

`next_state(state: LeitnerState, rating, rules, now) -> LeitnerResult`

* Box moves by `rating_box_delta`: `AGAIN` → box 1 (reset, increments `lapses`),
  `HARD` holds, `GOOD` +1, `EASY` +2; clamped to `[1, max_box]`.
* `due_at` is always scheduled **from now** using the new box interval — an
  overdue card does not pile up back-dated reviews.
* Non-AGAIN ratings increment `streak`.
* `score = rating_score[rating]`, scaled down by `lapse_score_penalty` on a
  lapse.
* Reasons: `BOX_MOVE`, `DUE`, `OVERDUE`, `MAX_BOX`, `LAPSE`.
* `is_due` / `due_sort_key`: never-reviewed cards are due and sort first, then
  most-overdue first.
* Deterministic; unknown rating raises `ValueError`.

## 3. Models

| Model | Key fields |
|---|---|
| `Flashcard` | `topic` → `planner.Topic`, optional `objective`, `curriculum_version`, `front_ar/fr`, `back_ar/fr` (LaTeX via `$...$`), `image`, `difficulty` 1–5, `status` (DRAFT/IN_REVIEW/PUBLISHED/RETIRED), `author` (Teacher), `reviewer`, `is_sample`, `external_id` (unique), review fields; same workflow as `Question` (`submit_for_review`/`publish`/`reject`/`retire`) |
| `FlashcardState` | `student`, `card`, `box` (≥1), `due_at` (nullable = new), `last_reviewed_at`, `streak`, `lapses`; unique `(student, card)` |
| `FlashcardReview` | `student`, `card`, `rating` (AGAIN/HARD/GOOD/EASY), `reviewed_at`, `response_ms`, `client_review_id`; unique `(student, client_review_id)` |
| `FlashcardsRuleSet` | `name`, `version`, `is_active`, `json` (schema-validated), `verified`; unique `(name, version)` |

`client_review_id` is nullable and only unique per student, so replays without an
id are unconstrained while replays with an id are deduplicated.

## 4. Service (`assessment/services_flashcards.py`)

* `due_cards(student, topic=, limit=, now=) -> (new_cards, review_cards)` —
  published cards only; new = no state; reviews = `due_at <= now`. Ordered most
  overdue → topic → id. New cards capped at `new_cards_per_day` minus new cards
  already seen today.
* `record_review(...) -> (review, state, replay)` — idempotent on
  `(student, client_review_id)`; a replay with a different card/rating is
  rejected. Advances Leitner state under `select_for_update`, writes the review
  and one `Evidence(source=FLASHCARD)` row in one transaction. The existing
  `Evidence` signal then refreshes topic mastery (A3).
* `new_cards_seen_today` / `stats`.
* `active_rules` / `active_rules_meta` — active DB rule set, else bundled
  default; a corrupt active row logs and falls back instead of raising.

## 5. Endpoints (`/api/assessment/`)

| Method | Path | Who | Behaviour |
|---|---|---|---|
| CRUD | `flashcards/` | teacher author / staff; students read published | authoring + workflow actions (`submit-for-review`, `publish`, `reject`, `retire`) |
| GET | `flashcards/due/?topic=&limit=` | student | due cards (new first, then reviews) with their state |
| POST | `flashcards/<uuid>/review/` | student | body `{rating, client_review_id?, response_ms?, reviewed_at?}`; idempotent replay |
| GET | `flashcards/stats/` | student | totals, due counts, box distribution |
| CRUD | `flashcard-rules/` | staff only | manage `FlashcardsRuleSet` rows |

Student endpoints require a student profile (`HasStudentProfile`) and are scoped
to `request.user.student`. Authoring reuses `QuestionPermission`, so teachers
edit their own DRAFTs and staff review.

## 6. Tests

* `assessment/tests_leitner.py` (pure, no DB) — 15 tests: reset/hold/+1/+2
  transitions, max-box clamp, box never below 1, overdue scheduled from now,
  streak/lapses, scores from rules, lapse penalty, determinism, unknown rating,
  `is_due` / `due_sort_key` ordering.
* `assessment/tests_flashcards.py` (DB) — 26 tests: state + evidence creation,
  AGAIN reset, offline replay idempotency (and mismatch rejection), unknown
  rating, due ordering, not-yet-due exclusion, daily new-card limit + same-day
  deduction, stats, review endpoint, draft 404, auth, due limit validation,
  topic filter, authoring permissions + publish, student sees only published,
  curriculum mismatch, rule-set API permissions.

`python manage.py test assessment` → **171 tests** (was 130 after A3).

## 7. Deliberately NOT in this phase

UI (web/mobile), planner integration, and any background worker (everything is
computed on demand). Flashcards create `Evidence` but do not yet drive the
planner.
