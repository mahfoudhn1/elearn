# Phase A1 — assessment content models, teacher API, import

Status: **implemented.** New Django app `backend/assessment/`, mounted at
`/api/assessment/`. Scope is *content only*: no quizzes, attempts, mastery,
flashcards or UI.

Companion docs: `docs/assessment/00_recon.md` (what existed first),
`docs/planner/phase-8.md` (curriculum), `docs/TO_VERIFY.md`.

---

## 1. Models (`backend/assessment/models.py`)

All models extend `core.models.UUIDModel`; the public id is the `uuid` (exposed
as `id`).

| Model | Fields |
|---|---|
| `Question` | `topic` FK → `planner.Topic` (PROTECT), `objective` FK → `planner.LearningObjective` (nullable), `curriculum_version` FK → `planner.CurriculumVersion` (PROTECT), `kind` (MCQ_SINGLE/MCQ_MULTI/TRUE_FALSE/NUMERIC), `prompt_ar`, `prompt_fr`, `image` (`ImageField`, nullable), `difficulty` 1–5, `est_seconds` (nullable), `explanation_ar`, `explanation_fr`, `status` (DRAFT/IN_REVIEW/PUBLISHED/RETIRED), `author` FK → `users.Teacher` (PROTECT), `reviewer` FK → `User` (nullable), `is_sample`, `source_note`, `external_id` (nullable, unique), `review_comment`, `reviewed_at`, timestamps |
| `QuestionOption` | `question` FK, `text_ar`, `text_fr`, `is_correct`, `misconception` FK (nullable), `order`; unique `(question, order)` |
| `Misconception` | `topic` FK, `code`, `description_ar`, `description_fr`; unique `(topic, code)` |
| `NumericAnswerSpec` | one-to-one `question`, `correct_value` Decimal, `tolerance_abs`/`tolerance_rel` Decimal (nullable, ≥ 0), `accepted_units` JSON (nullable) |

`curriculum_version` is stored redundantly (per the A1 spec) and validated to
match `topic.chapter.curriculum`. `Question.external_id` is normalised from `""`
to `NULL` so the unique constraint still allows many un-imported questions.

DB constraints: difficulty range, non-negative numeric tolerances, unique
option order, unique misconception code per topic, unique `external_id`.

## 2. LaTeX convention

**Chosen convention: dollar delimiters only.**

* inline math: `$...$` (e.g. `$x^2$`)
* display math: `$$...$$` (e.g. `$$\int_0^1 x\,dx$$`)

`\(...\)` and `\[...\]` are **not** used. The backend stores prompt/explanation
text verbatim and never parses or renders LaTeX; clients render it (KaTeX /
MathJax on web, a WebView or native renderer on mobile). The convention lives in
`assessment/constants.py`.

## 3. Validation

Draft authoring is incremental, so structural rules are **not** enforced on
every save. They are enforced at two gates: `submit-for-review` and `publish`
(and by the importer for rows whose `status` is `PUBLISHED`/`IN_REVIEW`).

`Question.validate_structure()`:

| Kind | Rule |
|---|---|
| `MCQ_SINGLE` | ≥ 2 options, exactly 1 correct |
| `MCQ_MULTI` | ≥ 2 options, ≥ 1 correct |
| `TRUE_FALSE` | exactly 2 options, exactly 1 correct |
| `NUMERIC` | a `NumericAnswerSpec` exists and no options are defined |

`Question.validate_publishable()`: `topic` set, prompt present in at least one
language, explanation present in at least one language.

Shared with the importer and serializers via
`assessment.models.option_structure_errors(kind, correctness)`.

## 4. Workflow

```
DRAFT --submit-for-review--> IN_REVIEW --publish--> PUBLISHED --retire--> RETIRED
                                   \--reject (comment required)--> DRAFT
```

Transition methods live on `Question` (`submit_for_review`, `publish`, `reject`,
`retire`) and raise Django `ValidationError` on an illegal transition; the API
converts these to HTTP 400.

## 5. Permissions

| Role | Who | Can |
|---|---|---|
| author | a `users.Teacher` | create; read/edit/delete **own DRAFT**; submit for review |
| reviewer | a staff user (`is_staff`) | read everything; publish / reject / retire |
| student | any authenticated non-teacher | read PUBLISHED questions only; never sees correct flags |
| anonymous | — | nothing |

A dedicated reviewer role is **out of scope for A1**; reviewer == staff. If a
teacher flag for reviewers is added later, change `assessment.permissions`.

Students never receive `is_correct`, `misconception`, `correct_value`,
`tolerance_*`, `review_comment`, `reviewer` or `external_id`; unpublished
questions are 404 for them.

## 6. API (`/api/assessment/`)

| Method | Path | Who |
|---|---|---|
| GET/POST | `questions/` | teachers (author), staff; students read published |
| GET/PATCH/PUT/DELETE | `questions/<uuid>/` | author (DRAFT only) / staff |
| POST | `questions/<uuid>/submit-for-review/` | author |
| POST | `questions/<uuid>/publish/` | reviewer |
| POST | `questions/<uuid>/reject/` | reviewer (comment required) |
| POST | `questions/<uuid>/retire/` | reviewer |
| GET/POST/… | `misconceptions/` | teachers/staff write, everyone reads |
| POST | `staff/import/` | staff; JSON body or uploaded CSV/JSON file |

Filters on `questions/`: `?topic=`, `?kind=`, `?status=` (author/staff only),
`?difficulty=`, `?is_sample=`, `?external_id=`, `?search=`.

## 7. Bulk import

Shared by `manage.py import_questions` and `POST /api/assessment/staff/import/`,
so the schema and error report are identical. Idempotent by `external_id`.
`dry_run` validates and writes nothing. Fatal field errors and (for
`PUBLISHED`/`IN_REVIEW`) structural errors skip the row; structural problems on
drafts are reported as warnings.

### JSON schema

```json
{
  "meta": {"description": "...", "verified": false},
  "misconceptions": [
    {"topic": "<topic-uuid>", "code": "SIGN_ERROR",
     "description_ar": "...", "description_fr": "..."}
  ],
  "questions": [
    {
      "external_id": "alg-1-001",
      "author": "<teacher-uuid>",
      "topic": "<topic-uuid>",
      "objective": "<objective-uuid>",
      "curriculum_version": "<uuid>",
      "kind": "MCQ_SINGLE",
      "prompt_ar": "...", "prompt_fr": "...",
      "difficulty": 3,
      "est_seconds": 60,
      "explanation_ar": "...", "explanation_fr": "...",
      "status": "DRAFT",
      "is_sample": false,
      "source_note": "...",
      "numeric": {
        "correct_value": "3.14",
        "tolerance_abs": "0.01",
        "tolerance_rel": null,
        "accepted_units": ["m"]
      },
      "options": [
        {"text_ar": "...", "text_fr": "...", "is_correct": true,
         "order": 1, "misconception_code": null}
      ]
    }
  ]
}
```

### CSV schema

One row per option; question fields repeat. `|`-separated `numeric_accepted_units`.

```
external_id,author,topic,objective,curriculum_version,kind,
prompt_ar,prompt_fr,difficulty,est_seconds,explanation_ar,explanation_fr,
status,is_sample,source_note,
option_order,option_text_ar,option_text_fr,option_is_correct,
option_misconception_code,
numeric_correct_value,numeric_tolerance_abs,numeric_tolerance_rel,
numeric_accepted_units
```

### Commands

```bash
python manage.py import_questions --author <teacher-uuid> --dry-run
python manage.py import_questions --author <teacher-uuid> \
    --path assessment/fixtures/questions.sample.json
```

The bundled `assessment/fixtures/questions.sample.json` is **fake**
(`verified: false`) and uses fixed placeholder UUIDs
(`...0000a1` curriculum, `...0000b1` topic) so tests can create matching
curriculum rows.

## 8. Admin

`QuestionAdmin` (list filters status/kind/difficulty/is_sample/curriculum, prompt
search, option + numeric-spec inlines), `MisconceptionAdmin`,
`NumericAnswerSpecAdmin`.

## 9. Tests

`assessment/tests.py` (structure + publishable + workflow validation),
`assessment/tests_api.py` (permissions, workflow transitions, student-safe
output), `assessment/tests_import.py` (dry-run, idempotency, row errors, CSV,
sample fixture, command, staff endpoint). Run `python manage.py test assessment`
→ 54 tests.

## 10. Deliberately NOT in this phase

Quizzes/attempts/grading, mastery, flashcards, student UI/web/mobile, a
dedicated reviewer role, LaTeX validation/rendering, and any automatic linking
of questions to lessons/groups.

## 11. Environment note

The local (gitignored) migration files were generated with Django 5.1 syntax
(`CheckConstraint(condition=...)`) while `requirements.txt` pins **Django
5.0.7** (and the models use `check=`). Three migration files
(`planner/0001`, `planner/0004`, `tracking/0003`) were normalised to
`CheckConstraint(check=...)` so the migration loader runs under the pinned
version. The change is semantics-preserving (same SQL constraint). The
`assessment/migrations/0001_initial.py` migration was generated under 5.0.7.
