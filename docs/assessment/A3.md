# Phase A3 — Mastery, readiness & trend

Status: **implemented.** Extends the `assessment` app with a pure mastery/
readiness engine, a schema-validated `MasteryRuleSet`, a cached `TopicMastery`
row and read endpoints. Mounted at `/api/assessment/`.

Out of scope (delivered later): flashcards, adaptive question selection, planner
integration, UI.

Companion docs: `docs/assessment/A1.md` (content models + teacher API),
`docs/assessment/A2.md` (quizzes + attempts + evidence),
`docs/assessment/00_recon.md`, `docs/TO_VERIFY.md`.

---

## 1. Rule set (JSON, schema-validated)

File: `backend/assessment/rules/mastery_default_v1.json`
Schema: `backend/assessment/mastery_schema.py` (`validate_mastery_rules`)
Loader/DTO: `backend/assessment/engine/mastery_rules.py` (`load_mastery_rules`)

Every number carries a sibling `why` string; the schema rejects a missing
`why`. All values are **placeholders** (`verified: false`) tracked in
`docs/TO_VERIFY.md`.

| Key | Meaning |
|---|---|
| `source_weights` | weight per `Evidence.Source` (QUIZ / PLANNER_EXERCISE / FLASHCARD / TEACHER_GRADE) |
| `difficulty_weights` | weight per difficulty 1–5 |
| `half_life_days` | exponential recency decay constant |
| `per_question_repeat_cap.window_days` | rolling window for the repeat cap |
| `per_question_repeat_cap.max_weight` | max total weight from one question inside the window |
| `confidence.min_effective_weight` | below this (or below `min_distinct_days`) confidence is NONE |
| `confidence.min_distinct_days` | evidence must span at least this many days |
| `confidence.low_fraction` | LOW below `min_effective_weight / low_fraction` |
| `readiness.coverage_min` | minimum topic coverage before a readiness value is reported |
| `readiness_bands.{weak,developing,secure}_max` | band cut points |
| `trend.window_days` | recent-vs-prior comparison window |
| `trend.min_effective_weight` | per-side minimum weight for a trend |
| `trend.delta_threshold` | mastery delta needed for UP/DOWN |

## 2. Pure engine (`assessment/engine/`)

No Django, no DB, no clock: callers pass `now` in.

### `mastery.py`

`compute_topic_mastery(evidence, rules, now) -> TopicMasteryResult`

```
weight = source_weight
         x difficulty_weight
         x exp(-age_days / half_life_days)
         x weight_modifier
         x repeat_cap_factor
mastery = sum(w x score) / sum(w)
```

* `repeat_cap_factor` is computed oldest-first so each observation is capped
  against the same question's observations inside the window **ending at that
  observation**; repeats more than `window_days` apart start a fresh budget.
  The factor is clamped to `[0, 1]` — the cap only **limits** weight, it never
  inflates a lone observation past its own source/difficulty weight.
* `TopicMasteryResult`: `mastery` (`None` when confidence is NONE), `confidence`,
  `trend`, `effective_weight`, `evidence_count`, `last_evidence_at`, `reasons`.
* Confidence: NONE below `min_effective_weight` **or** `min_distinct_days`;
  otherwise LOW / MEDIUM / HIGH by weight bands.
* Trend: compares the `trend.window_days` recent window against the equally
  sized prior window; UP/DOWN past `delta_threshold`, else FLAT, and UNKNOWN
  when either side lacks `min_effective_weight`.
* Every term appends a `Reason(code, params)` (`EVIDENCE`, `SOURCE_WEIGHT`,
  `DIFFICULTY_WEIGHT`, `RECENCY`, `REPEAT_CAP`, `LOW_CONFIDENCE`,
  `TREND_UP`/`DOWN`/`FLAT`/`UNKNOWN`). Reason codes, not prose.
* Deterministic: input order does not matter (rows are sorted internally).

### `readiness.py`

`compute_readiness(topics, rules, scope) -> ReadinessResult` and the
`compute_chapter_readiness` / `compute_subject_readiness` helpers.

* Topics with confidence **NONE are excluded from the mean** but **counted in
  coverage** (they were observed, we just cannot trust the number yet).
* `coverage = topics_with_evidence / topics_total`; below `coverage_min` the
  value is withheld (`value=None`, band `NONE`).
* Contributing topics are weighted (chapter/topic weight, default 1.0).
* `confidence` is the weakest contributing topic's confidence.
* Bands from `readiness_bands`; reasons `COVERAGE`, `WEIGHTED_MEAN`,
  `INSUFFICIENT_COVERAGE`, `NO_TOPICS`, `BAND`.

## 3. Persistence

### `MasteryRuleSet` (new model)

Mirrors `planner.PedagogyRuleSet`: `name`, `version`, `is_active`, `json`,
`verified`, timestamps; `save()`/`clean()` validate the JSON. Unique
`(name, version)`.

### `TopicMastery` (new model) — the cache

`student`, `topic`, `mastery` (nullable), `confidence`, `trend`,
`effective_weight`, `evidence_count`, `last_evidence_at`, `computed_at`,
`rules_version`, `reasons` (JSON). Unique `(student, topic)`; table check
`mastery IS NULL OR 0 <= mastery <= 1`.

It is a **cache, always overwritten (never incremented)**:
* a `post_save` signal on `Evidence` recomputes the (student, topic) row in
  `transaction.on_commit` (`assessment/signals.py`, wired in `apps.py`);
* reads also heal lazily via `ensure_topic_mastery` (missing, stale after
  `STALE_AFTER = 24h`, or `rules_version` mismatch);
* a corrupt active rule set falls back to the bundled default instead of
  raising.

Chapter/subject readiness is **computed on read** from the cached topic rows
(`services_mastery.compute_chapter_result` / `compute_subject_result` /
`overview`) — nothing is persisted for them.

## 4. Endpoints (`/api/assessment/`)

| Method | Path | Who | Behaviour |
|---|---|---|---|
| GET | `mastery/topics/?subject=&chapter=` | student | cached `TopicMastery` rows for the student, optionally scoped |
| GET | `mastery/chapters/?subject=` | student | chapter readiness (value/band/coverage/confidence/reasons) |
| GET | `readiness/subject/<subject>/` | student | subject readiness, addressed by subject string |
| GET | `readiness/overview/` | student | readiness for every subject the student has evidence on |
| CRUD | `mastery-rules/` | staff only | manage `MasteryRuleSet` rows (JSON validated) |

All student endpoints require a student profile (`HasStudentProfile`) and are
scoped to `request.user.student`, so another student's data is never visible.

## 5. Tests

* `assessment/tests_mastery.py` (pure, `SimpleTestCase`, no DB) — 22 tests:
  empty evidence; recent beats old; hard-correct beats easy-correct; repeat cap
  (capped + window-scoped); little evidence -> NONE/LOW and no number;
  single-day never confident; all-correct / all-wrong; partial scores;
  determinism (shuffled input); confidence levels; trend UP/FLAT/DOWN and
  UNKNOWN; last-evidence timestamp; coverage gate; NONE-confidence excluded
  from mean but counted; weighted mean; bands; weakest-contributor confidence;
  chapter/subject helpers; readiness determinism.
* `assessment/tests_mastery_api.py` (DB) — 17 tests: recompute creates/
  overwrites the cache; signal recomputes on commit; lazy staleness; rule
  version invalidation; active-rule fallback (valid + corrupt); the four read
  endpoints; auth/student-profile/other-student isolation; rule-set API
  permissions + invalid-JSON rejection.

`python manage.py test assessment` → **130 tests** (was 91 after A2).

## 6. Deliberately NOT in this phase

Flashcards, adaptive question selection, planner integration (weak topic ->
demand / `sync_planned_session_from_study_session`), UI/web/mobile, a
`TEACHER_GRADE` evidence writer, and any background worker (recompute is
signal-driven plus lazy on read, matching the planner's no-Celery pattern).
