# Phase A5 — Adaptive diagnostic

Status: **implemented.** Adds an adaptive question selector to the `assessment`
app and wires it into `Quiz.kind == DIAGNOSTIC`. Mounted at
`/api/assessment/`.

Out of scope (delivered later): UI, planner integration.

Companion docs: `docs/assessment/A1.md` (content), `A2.md` (quizzes + evidence +
attempts), `A3.md` (mastery + readiness), `A4.md` (flashcards),
`docs/TO_VERIFY.md`.

---

## 1. Rule set (JSON, schema-validated)

File: `backend/assessment/rules/adaptive_default_v1.json`
Schema: `backend/assessment/adaptive_schema.py` (`validate_adaptive_rules`)
Loader/DTO: `backend/assessment/engine/adaptive_rules.py` (`load_adaptive_rules`)

Every number carries a sibling `why`; the schema rejects a missing `why`. All
values are **placeholders** (`verified: false`) tracked in `docs/TO_VERIFY.md`.

| Key | Meaning |
|---|---|
| `start_difficulty` | a topic's initial target difficulty |
| `difficulty_step` | how far the target moves per answer |
| `difficulty_min` / `difficulty_max` | target clamp |
| `min_questions_per_topic` | per-topic quota that defines coverage |
| `max_questions` | hard cap on a diagnostic session |
| `skip_recent_days` | window in which a seen question is skipped |
| `prefer_untested_misconceptions` / `misconception_bonus` | prefer questions probing unseen misconceptions |
| `coverage_round_robin` / `stop_when_covered` | coverage policy |

## 2. Pure engine (`assessment/engine/adaptive.py`)

No Django, no DB, no clock.

`select_next_question(state, candidates, rules, seed) -> AdaptiveDecision`

* **Coverage first** — topics below `min_questions_per_topic` are served in a
  stable round-robin order.
* **Difficulty staircase per topic** — target starts at `start_difficulty` and
  moves `difficulty_step` up on a correct answer, down on a wrong one, clamped
  to `[difficulty_min, difficulty_max]` and to what the bank offers.
* **Skip recent** — questions in `state.recently_seen_ids` are never picked.
* **Prefer untested misconceptions** — a question that probes a misconception
  not yet tested scores better.
* **STOP** with a reason: `COVERED`, `MAX_LENGTH`, `TIME_LIMIT` (caller-side),
  `NO_CANDIDATES`, or `INSUFFICIENT_QUESTIONS` (a topic's bank is thinner than
  its quota — reported, never raised).
* Deterministic tie-break: score, then the seeded stable order, then question id.

Supporting DTOs: `AdaptiveCandidate(question_id, topic_id, difficulty,
misconception_ids, is_published)`, `AdaptiveState(...)` and
`apply_answer(state, question_id, topic_id, is_correct, rules, ...) -> state`.

## 3. Integration

* `QuizAttempt.adaptive_state` (new JSONField) stores the session state, so a
  reload reproduces the session and STOP reasons are stable.
* `services.start_attempt` — a DIAGNOSTIC quiz does **not** pre-select questions;
  it builds the candidate bank and initialises the adaptive state.
* `services.record_answer` — advances the persisted staircase after each answer.
* Other quiz kinds keep their A2 pre-selected `question_ids` behaviour.

## 4. Endpoints (`/api/assessment/`)

| Method | Path | Who | Behaviour |
|---|---|---|---|
| POST | `attempts/<uuid>/next/` | student (owner) | returns the next adaptive question (student-safe) or `{stopped: true, stop_reason, insufficient_topics}`. Idempotent while the served question is unanswered. 400 for a non-adaptive quiz. |
| POST | `attempts/<uuid>/answer/` | student (owner) | unchanged; also advances the adaptive state |
| GET | `attempts/<uuid>/result/` | student (owner) | for DIAGNOSTIC adds `diagnostic`: `per_topic` mastery (with confidence/trend/evidence_count/reasons) + `detected_misconceptions` (code + topic) + `insufficient_topics` + `stop_reason` |

## 5. Tests

* `assessment/tests_adaptive.py` (pure, no DB) — 14 tests: coverage guaranteed,
  no repeats, difficulty up/down + clamp, skip recent, prefer untested
  misconception, stop at max length, insufficient reported not raised, no
  candidates, same seed → same sequence, state updates.
* `assessment/tests_adaptive_api.py` (DB) — 10 tests: DIAGNOSTIC start does not
  pre-select, next serves then stops covered, next idempotent while pending,
  stop payload reason, non-adaptive 400, thin bank → `INSUFFICIENT_QUESTIONS`,
  result per-topic mastery + detected misconceptions, same seed → same sequence
  (fresh student per run), recent-history skipping, auth.

`python manage.py test assessment` → **195 tests** (was 171 after A4).

## 6. Deliberately NOT in this phase

UI (web/mobile), planner integration, and any background worker. The time limit
is enforced by the existing attempt-expiry path (A2), not by the selector.
