# Phase A10 — Item analysis, calibration, performance & abuse

Status: **implemented.** Adds psychometric item analysis for reviewers, a staff
calibration report, performance guards, abuse protection, golden scenarios and
the assessment architecture/rules docs.

Companion docs: `ARCHITECTURE.md`, `RULES.md`, `A1.md`–`A9.md`,
`docs/TO_VERIFY.md`.

---

## 1. Item analysis

Rules: `assessment/rules/item_analysis_default_v1.json` (schema
`item_analysis_schema.py`, loader `engine/item_analysis_rules.py`) — every number
has a `why`.

Pure engine `assessment/engine/item_analysis.py`:
`analyse_item(responses, rules, correct_option_id) -> ItemAnalysisResult` with
`attempts`, `correct`, `pct_correct`, `avg_time_s`, `discrimination` (top minus
bottom `top_bottom_fraction`, ranked by attempt score), `option_distribution`,
and flags:
`INSUFFICIENT_DATA`, `TOO_EASY`, `TOO_HARD`, `LOW_DISCRIMINATION`,
`NEGATIVE_DISCRIMINATION`, `AMBIGUOUS_DISTRACTOR` (the correct option is excluded
from the distractor check).

Service `assessment/item_analysis.py` loads a question's `AttemptAnswer` rows
(with the attempt's score) and returns dicts.

Endpoint `GET /api/assessment/item-analysis/?question=<uuid>` (or `?quiz=<uuid>`):
visible to **staff reviewers and the question's author** only (403 otherwise;
never to students). Questions can be **RETIRED** through the existing workflow
(`QuestionViewSet.retire`), which item analysis surfaces by flagging weak items.

## 2. Calibration report

`TeacherGrade` (new model): `student`, `subject`, `score`, `max_score`,
`recorded_by`, `recorded_at`, `source_note`; unique `(student, subject)`.

* Teachers record grades for their own students: `POST /api/assessment/teacher/grades/`
  (403 for a student outside the teacher's groups/subscriptions).
* Staff read `GET /api/assessment/staff/calibration/`:
  `{graded_students, min_samples, subjects: [{subject, n, correlation,
  significant, mean_readiness, mean_grade}]}`. Correlation is Pearson r
  (`engine/calibration.py`) between subject readiness (A3) and the grade ratio,
  with the sample size; `significant` requires `n >= calibration_min_samples`.

## 3. Performance

* `tests_item_analysis.py` asserts a topic mastery recompute takes **<100ms**
  (50 evidence rows) and `ensure_topic_mastery` runs within a **≤10-query
  budget**.
* Index review → migration `0006_teachergrade_and_more` adds
  `AttemptAnswer(question, is_correct)`, `AttemptAnswer(misconception)`,
  `TeacherGrade(subject)`. `Evidence(student, topic, occurred_at)` and
  `TopicMastery(student, computed_at)/(topic)` already existed.

## 4. Abuse protection

* `AttemptStartView` uses `ScopedRateThrottle` with scope `attempt_start`
  (`DEFAULT_THROTTLE_RATES['attempt_start'] = '30/min'`; placeholder). A test
  forces a 2/min rate and asserts the third request is 429.
* Repeat-cap tests: 41 retakes of one question stay at/under the per-question
  repeat-cap weight, and the golden retake scenario pins the same behaviour.

## 5. Golden scenarios

`assessment/golden_scenarios.py` + `management/commands/write_assessment_golden.py`
write `assessment/tests/golden/assessment_scenarios.json`; `tests_golden_scenarios.py`
compares the current engines against it:

* **new student** — no mastery, no number;
* **strong student** — mastery 1.0, HIGH confidence;
* **misconceptions** — an ambiguous distractor is flagged;
* **repeated retakes** — 41 same-question answers stay capped;
* **thin question bank** — adaptive reports `INSUFFICIENT_QUESTIONS`;
* **weak student in a LIGHT subject** — mastery is still tracked while planner
  time stays within the LIGHT ceiling.
